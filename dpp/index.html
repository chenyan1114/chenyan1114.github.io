簽好的 VC 被壓縮後放進網址的 #vc=…，手機打開時會自動解開並驗證。# 後面的內容不會傳給網站伺服器。

        

        

      

    

    
改 VC 裡任何欄位的值再驗證就會失敗；只改排版或欄位順序不影響。

    

      技術細節
      
    
        
  • 簽名：proof options 與 VC 各自 JCS 正規化 → SHA-256 → 串接 → 用簽名金鑰簽名 → proofValue，連同 proof options 成為 proof。
    • 
        
  • did:key → eddsa-jcs-2022（W3C 標準），驗證用 DID 內的公鑰。
    • 
        
  • did:web → 同樣用 eddsa-jcs-2022，驗證時從 https://網域/.well-known/did.json 下載 DID 文件取得公鑰；
          尚未放上網站時，以本頁暫存的文件模擬並提醒。
    • 
        
  • did:ethr → ecdsa-secp256k1-recovery-jcs-demo（教學用，非標準）：從簽名回推地址，
          再比對 DID 文件裡的 #controller 或 #delegate-N；連不上 RPC 時離線判定。
    • 
        
  • VC v2.0：validFrom／validUntil 取代 v1 的 issuanceDate／expirationDate，皆為選填的 ISO 8601 日期時間。
    • 
        
  • 驗證結果：✗ 違反 v2.0 規範或簽名不符；⚠ 只是本 demo 的預期（如 urn:uuid、ISO claims、與表單不同）。
    •

4. VP：持有人出示

    
持有人把 VC 包成 VP（Verifiable Presentation），用自己的私鑰簽名後交給驗證者。

第一階段：靜態驗證

          
只驗簽章與持有人綁定，不檢查受眾和 challenge：同一份 VP 交幾次都會通過。

          

          

        

      

    

    
把簽好的 VC 放進錢包，再按「產生並簽署 VP」。

    

      技術細節
      
    
        
  • VP = holder + verifiableCredential[]，整份由持有人私鑰簽名：proofPurpose: authentication，
          verificationMethod 必須屬於 holder DID。
    • 
        
  • 持有人綁定：每張 VC 的 credentialSubject.id 必須等於 VP 的 holder，拿別人的 VC 會失敗。
    • 
        
  • 第二階段：驗證者發出一次性的 challenge（有期限）和自己的識別碼 domain，持有人把兩者放進 proof 一起簽。
          驗證者會拒絕：domain 不是自己（AudienceMismatchError）、不是自己發的 challenge（ChallengeMismatchError）、
          過期（ChallengeExpiredError）、用過（ChallengeReusedError）。
    •

      技術細節
      
      
        
    • QR code 只放網址（credential_offer_uri）。每次掃描，後端都產生新的一次性領證碼，所以大家掃同一個 QR code 也互不干擾。
      • 
        
    • 領證：預授權碼流程。錢包用領證碼換 access token，再用自己的金鑰簽一個含 c_nonce 的 proof，
          後端發出綁定該金鑰（cnf.jwk）的 SD-JWT VC（dc+sd-jwt）。
      • 
        
    • 出示：請求帶一次性 nonce（＝challenge）和驗證者的 client_id（＝受眾），整份請求由後端憑證簽章。
          錢包只揭露被要求的欄位，並附上 Key Binding JWT（aud、nonce、sd_hash）。
      • 
        
    • 後端拒絕：受眾不對（AudienceMismatchError）、nonce 不對（ChallengeMismatchError）、
          過期（ChallengeExpiredError）、重送（ChallengeReusedError），與第 4 卡相同。
      • 
        
    • 後端憑證是自簽的示範憑證，不在歐盟信任清單上；正式錢包可能顯示警告或拒絕。
